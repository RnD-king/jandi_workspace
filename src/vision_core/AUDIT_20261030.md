## 중복·구조 점검

- 발행한 모션의 소유권은 `ControlCommandCoordinator` 한 곳에 유지한다. 완료를
  만들어 내거나 READY를 DONE으로 취급하지 않는다. 반복 계획기는 별도 실행 큐가 아니다.
- 공통 접근 router는 목표 경로·후보·락·근거리 인계를 담당하고, 공/골대/허들
  컨트롤러는 자신의 미세 정렬·미션 동작·복구 FSM을 담당한다.
- 깊이 복구는 원거리/근거리가 같은 `GoalController::StepDepthRecovery`를 사용한다.
  해제 함수도 같은 컨트롤러에 두어 외부에서 내부 FSM을 복제하지 않는다.
- 골대의 더 이상 진입하지 않는 COARSE 깊이 복구 분기와 사용되지 않는
  `SearchRecoveryAction`을 제거했다. 외부 상태 번호가 달라지지 않게 enum 번호는
  예약 상태로 보존하고, 예약 상태는 발 전환으로만 연결한다.
- 중복 관측 폐기는 공통 함수에 모았다. 공의 DOWN WALK 전환 임계값 및 골대의
  COARSE 거리 임계값은 코어·설정·rqt에서 제거된 상태를 확인했다.
- 기존 정지 진입을 가정한 테스트는 수동 승인 계약을 명시하거나 새 AUTO 경로의
  기대값으로 갱신했다. 실전 AUTO의 보행/유실/근거리 인계는 전용 회귀 코드로 검사한다.
- `mission_controller.cpp`에는 추적·시험 시작·관측·전송 조정이 여전히 많이 모여 있다.
  파일이 짧아졌다는 이유로 구조가 단순해졌다고 주장하지 않는다. 이번에는 실행 계약을
  바꾸는 전체 FSM 재작성 대신 실제 충돌 경로와 죽은 분기를 정리했다.

## 검증 범위와 남은 확인

코어/테스트 컴파일, 코어 설치, ROS `vision`·`forward_walk` 빌드와 diff 공백 검사를 완료했다.
설치 라이브러리와 YAML은 빌드/원본 파일과 SHA-256이 같고, 두 ROS 패키지의 CMake 캐시는
모두 `/home/noh/vision_core/install`을 가리킨다. ROS Humble의 기존 CMake 개발용
CMP0148/CMP0144 경고는 남아 있지만 두 패키지 빌드는 종료 코드 0으로 완료됐다.
테스트 실행 결과는 만들지 않았다. 검증 명령은 다음과 같다.

```bash
ctest --test-dir /home/noh/vision_core/build_shoot --output-on-failure
cd /home/noh/my_cv
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon test --packages-select vision forward_walk --event-handlers console_direct+
colcon test-result --verbose
```

카메라 외부 보정값은 요청대로 임시 right=0, forward=0, height=.45 m,
FORWARD pitch=20°, GOAL pitch=0°다. 실제 카메라 장착 오프셋·각도와 LINE의
로봇 기준 픽셀을 함께 확인해야 한다. 임시값으로 실제 객체 접근 정확도를 보장하지 않는다.
실제 모션 JSON의 보폭과 로봇 균형, 모터 도착·슛 궤적도 하드웨어 확인이 남아 있다.
